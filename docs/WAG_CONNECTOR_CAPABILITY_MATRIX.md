# WAG Connector Capability Matrix

**One executive question this module answers: for any given metric, is it real, automatable, first-party evidence — or a Studio-only number no future agent should assume it has?**

Every row below was verified against Google's current, official YouTube Data API v3 and YouTube Analytics API v2 reference documentation on 2026-08-11 (links inline per section), not assumed from prior general knowledge. Where a Studio-displayed metric has no confirmed API equivalent, it is marked unavailable rather than mapped to a similarly-named field that isn't actually the same thing. This is the permanent reference every future WAG OS specialist (Greenlight, Packaging, Hook & Retention, Audience Intelligence, Format Intelligence) should check before assuming a number is obtainable automatically.

**Scope:** this matrix covers what is available to WAG as the channel *owner* via OAuth (`youtube.readonly` + `yt-analytics.readonly` scopes — the two scopes WAG OS's connector currently requests, per Katie's 2026-08-10 directive). It does not cover monetary/revenue scopes (`yt-analytics-monetary.readonly`), which WAG OS deliberately does not request today.

---

## Bucket legend

- **A — Directly available through the official API.** Real, queryable, first-party, at the granularity stated.
- **B — Available through the API, but with a real limitation** (lag, coarser granularity than Studio shows, requires combining multiple calls, or requires an approximation rather than an exact Studio-label match).
- **C — Available only through Studio's UI or a manual CSV export**, not through either public API.
- **D — Not reliably available anywhere**, or not documented by Google at all (includes Studio-only AI features with no data contract).

## What this means for the historical-ingestion and intelligence-layer work ahead

Everything marked **A** or **B** above and not yet ingested (retention curves, traffic sources, subscribers gained/lost, geography, demographics, playlist performance, the true Analytics-API likes/comments time series, and Shorts segmentation) is real, available, first-party evidence WAG OS is not yet capturing. The current `youtube-sync` vertical slice deliberately proved provenance and storage correctness first, on a small batch, before expanding query surface — per Katie's original 12-point directive. Expanding to these fields is a scope decision for the historical-ingestion phase, not a capability question — the capability already exists and is documented above.

Everything marked **D** (thumbnail impressions, impressions CTR, new-vs-returning viewers, unique viewers) is a genuine, permanent blind spot for any *programmatic* WAG OS system. These numbers only exist inside YouTube Studio's own UI. If a future specialist needs them, the only path is a manual Studio pull recorded as a dated, sourced snapshot (the same honest pattern already used in `WAG_MEASUREMENT_STANDARDS.md`) — never invented, estimated, or silently substituted with a similarly-named API field.
