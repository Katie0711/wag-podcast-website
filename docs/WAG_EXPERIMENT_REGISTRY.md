# WAG Experiment Registry

**One executive question this module answers: what are we actually testing right now, and what did it teach us?**

**Part of the WAG YouTube Growth Operating System.** A named, structured registry — every real question this research pass raised that WAG could test directly on its own channel, instead of importing another creator's answer wholesale. Each entry: **Hypothesis -> Execution -> Result -> Decision.** An experiment stays honestly marked "not yet run" until it actually has real result data — never backfilled with a guessed outcome.

**Why this exists as its own doc, not folded into another one:** `WAG_PATTERN_LIBRARY.md` holds evidence from *other* creators; `WAG_VIDEO_GREENLIGHT.md` holds *WAG's own* idea-level records. This registry is different from both — it holds specific, narrow, testable questions (often smaller than a whole video) that get resolved with WAG's own real data over time, the same discipline `WAG_MEASUREMENT_STANDARDS.md` uses for thresholds.

---

## The record shape

| Field | What it holds |
|---|---|
| Experiment name | Short, memorable, reusable |
| Real question | The specific, narrow thing being tested |
| Source pattern | Which `WAG_PATTERN_LIBRARY.md` entry (or real WAG observation) raised this question |
| Hypothesis | What WAG expects, stated before any data exists |
| Execution plan | Exactly how to run it — real, concrete, low-cost where possible |
| Status | Not yet run / Running / Complete |
| Result | Real data only, once it exists |
| Decision | Adopt / Reject / Inconclusive-retest, with reasoning |

## Data-model note (per the WAG OS module-lens habit)

If this ever became software: one `Experiment` record (Name, Real question, Source pattern reference, Hypothesis, Execution plan, Status, Result, Decision) — many experiments could share a source pattern, and a `VideoIdea` (`WAG_VIDEO_GREENLIGHT.md`) could reference the experiment(s) it's designed to help resolve. No UI/app implied — just the shape, and the same non-negotiable rule as everywhere else in WAG OS: a Result field only gets filled with real, published performance data, never a guess dressed up as a placeholder.
